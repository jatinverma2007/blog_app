# Deployment

The app can be deployed as one Render web service or as a Vercel frontend with
a Render backend.

## Render

Create a Render Blueprint from the repository root using `render.yaml`. It
builds the frontend and backend from `MERN-Blog`, starts the Express server,
and checks `/healthz` before marking the service healthy. Set `MONGO_URI` to a
MongoDB connection string reachable by Render. `SECRET_KEY` is generated by
the Blueprint. Set `CLOUD_NAME`, `API_KEY`, and `API_SECRET` to enable image
uploads through Cloudinary.

If configuring the Render service manually, use:

- Root directory: `MERN-Blog`
- Build command: `npm ci && npm run build`
- Start command: `npm start`
- Health check path: `/healthz`
- Required environment variables: `MONGO_URI`, `SECRET_KEY`
- Optional image-upload variables: `CLOUD_NAME`, `API_KEY`, `API_SECRET`

Set `FRONTEND_URL` (and optionally `FRONTEND_URL_2`) to the exact HTTPS
origins that should be allowed to make credentialed requests to the API.
Comma-separated origins are supported.

## Vercel frontend

Import the repository in Vercel and set the project root directory to
`MERN-Blog/frontend`. Vercel detects Vite's build command and `dist` output.
The frontend uses relative API paths in production; `frontend/vercel.json`
proxies `/api/*` to the Render backend and provides the SPA fallback. If the
Render URL changes, update the API rewrite destination there. The backend must
also allow the Vercel site origin via `FRONTEND_URL`.

Do not commit production credentials or `.env` files. Ensure the MongoDB
provider's network access rules allow connections from the deployed Render
service.
